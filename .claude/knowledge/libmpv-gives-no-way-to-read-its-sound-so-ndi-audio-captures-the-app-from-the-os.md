## libmpv gives no way to read the sound it plays, so the NDI output's audio captures the app's own processes from the OS
**Area:** projection
**Trigger:** touching `native/engine/ndi-audio*.{h,cpp,mm}` or the NDI sound; a receiver with no sound, sound out of step, or a macOS permission prompt about recording audio

- There is no libmpv audio callback (the `audio-cb` PR #5566 was closed unmerged), `ao=pcm` is untimed (plays faster than real time), `ao=null` drops the sound, and mpv's audio graph ends in one output. Web Audio would need CORS on every `worship://` response and still never reaches the engines. So the NDI sender captures the app's process tree from the OS: Windows 10 2004+ WASAPI process loopback of Electron main (`--parent`, `INCLUDE_TARGET_PROCESS_TREE`; mingw lacks `audioclientactivationparams.h`, its 4 declarations are written by hand; nothing arrives while the app is silent, so it is polled and the gaps filled); macOS 14.2+ a Core Audio process tap of main + `proc_listchildpids(main)` — Chromium plays from its audio-service helper, a child — re-targeted when `kAudioHardwarePropertyProcessObjectList` changes (a new engine joins); Linux the default output's monitor through libpulse-simple (the whole computer).
- **macOS permission:** the first `AudioDeviceStart` asks for «System Audio Recording» on behalf of the *responsible* process — the app (needs `NSAudioCaptureUsageDescription` in its Info.plist), or the terminal when Playwright launched it. Before it is answered the IOProc never fires (0 samples, not zeros); after a refusal it gets silence with no error — hence the level in the status.
- **Sync:** both stamped on one clock (NDI's 100 ns epoch base): the picture when painted, the sound when captured (minus the buffer's age from its host time / QPC). Measured with a flash+beep file and `ndi-probe avsync`: the engine's own sound came ~60–70 ms before its picture (the frame still crosses main and the page), so the engine holds a video's sound 50 ms (`audio-delay`), which also fixed the room (Mac screen+speakers via ScreenCaptureKit: engine −61 → −12 ms, Chromium −11 ms). Chromium's NDI offset varies by start (+1…+51 ms): the NDI window plays its own muted `<video>` beside the projector's.
- An A/V test file must have no B-frames in an AVI: with no presentation times the decoder shows them two frames late — 65 ms of false lag (agent2v, 2026-11-10).
